Ch2Motivation, Maslow, Selective Perception

  • Extrinsic = ใช้เพราะสิ่งตอบแทน (Points, Discounts, Rewards) · Intrinsic = ใช้เพราะพอใจ (Fun, Connection, Community) (p25)

Maslow's Hierarchy (ฉบับ UX, p26) ล่าง→บน

  1. Functional: ทำงานได้จริง, No bugs
  2. Reliability: โหลดเร็ว ปลอดภัย พร้อมใช้, cancel/undo ได้
  3. Usability: ใช้ง่าย, F/Z pattern
  4. Convenience: ลดขั้นตอน ประหยัดเวลา
  5. Pleasurable: UI สวย interaction ดี น่าประทับใจ

Ch2Organization, Interpretation, Cognitive Load

Gestalt Theory (p37): มองภาพรวมมากกว่าส่วนย่อย

  • 5 กฎ: Proximity (ใกล้ชิด) · Closure (สิ้นสุด/เติมเต็ม) · Similarity (คล้าย) · Continuation (ต่อเนื่อง) · Prägnanz (ชัดเจน/เรียบง่าย)
  • Reproductive = ใช้ความรู้เดิมแก้ปัญหาใหม่ · Productive = สร้างความรู้ใหม่ตามสถานการณ์

Affordance 6 ประเภท (p39): มองแล้วรู้ว่าต้องทำอะไร

  • Pattern: ธรรมเนียมจนคุ้นเคย (ลิงก์ขีดเส้นใต้)
  • Explicit: บอกชัดด้วยข้อความ/รูปทรง ("Buy Now")
  • False: ดูเหมือนกดได้แต่ทำอย่างอื่น/ไม่ได้
  • Metaphorical: เลียนแบบของจริง (ถังขยะ, แผ่นดิสก์)
  • Hidden: โผล่เมื่อต้องการ (hover menu)
  • Negative: ดูเหมือน inactive แต่ active

Cognitive Load 3 ประเภท (p41)

  • Intrinsic: ความยากโดยธรรมชาติของงาน (coding)
  • Extraneous: ภาระส่วนเกินจากการนำเสนอไม่ดี (หน้าเว็บสับสน) ← ดีไซเนอร์ต้องลด
  • Germane: ภาระที่มีประโยชน์ เชื่อมความรู้เดิมกับใหม่

Cognitive Overload (เมนูข้อมูลเยอะ) ป้องกัน 5 ข้อ: Less is more · Chunking · Progress Indicators · Image Identifying · Familiarity (p43)

Ch2Design Laws 6 ข้อ (p45–68)

Lawแก่นแท้ใช้/ตัวอย่าง
Hick'sเวลาตัดสินใจ ↑ ตาม จำนวน+ความซับซ้อนของตัวเลือก (เน้น "ความคิด")ลดตัวเลือก, Categorization, Progressive Disclosure/step-by-step form, Spotify nav
Fitts'sเวลาไปถึงเป้า ขึ้นกับ size + distance (เน้น "การเคลื่อนไหว")CTA ใหญ่, วางที่ขอบ/มุมจอ, Spacebar ใหญ่, ปุ่ม Delete เล็ก+ไกล, thumb zone
Miller'sความจำระยะสั้น 7 ± 2 (5–9) ชิ้น · Cognitive LimitationChunking, เมนูหลัก ≤ 7, แบ่งฟอร์ม
Jakob'sผู้ใช้คาดหวังให้เว็บเราทำงานเหมือนเว็บอื่นที่คุ้นเคย (Familiarity Breeds Intuition)ตะกร้ามุมขวาบน, ตัวอย่างการขับรถยี่ห้อใหม่ · หลักสำคัญ = Mental Models
Parkinson'sงานขยายตัวจนเต็มเวลาที่มี (Focus on Essential/Process)Autofill, แบ่งฟอร์มสั้น, ตัดฟิลด์ไม่จำเป็น · กราฟ effort: เวลาน้อย=พยายามมาก, มีจุด best time
Tesler'sความซับซ้อนกำจัดไม่ได้ (Conservation of Complexity) ทำได้แค่ ย้ายว่าใครรับให้ระบบรับแทนผู้ใช้: Uber คำนวณเส้นทาง/ราคา, Grab จำที่อยู่, จำรหัสผ่าน

กับดัก: Hick = จำนวนตัวเลือก/การตัดสินใจ · Fitts = ขนาด/ระยะ · Miller = ความจำ · Tesler = ย้ายความซับซ้อน · Parkinson = เวลา/ขั้นตอน

Ch2Mental Model, Serial Position, Least Effort

Mental Models 3 แบบ (p71)

  • User Mental Model: ผู้ใช้คาดว่าระบบทำงานอย่างไร (จากประสบการณ์)
  • System/Implementation Model: ระบบทำงานจริงตาม code/database
  • Designer's Conceptual Model: สะพานที่ดีไซเนอร์สร้างให้ UI ตรงกับความคิดผู้ใช้

Thinking & Decision Making (p72): System 1 = สัญชาตญาณ เร็ว อัตโนมัติ ใช้อารมณ์ · System 2 = วิเคราะห์ ช้า ใช้เหตุผล

Decision Matrix (p73–74): คะแนน = W (น้ำหนัก) × S (คะแนนดิบ) รวมกัน → Tablet 51, Mobile 56, Barcode gun 65 (ชนะ)

Serial Position Effect (p76–77)

  • จำ "ตัวแรก" และ "ตัวสุดท้าย" ได้ดี ตรงกลางลืม
  • Primacy = จำตัวแรก → Long-term Memory · Recency = จำตัวท้าย → Short-term Memory
  • ใช้: ของสำคัญไว้หัว/ท้ายเมนู · pricing: ถูกสุดไว้แรก แนะนำไว้ท้าย

Von Restorff / Isolation Effect (p78–79)

สิ่งที่แปลกแยกจะถูกจำ (Pattern Recognition → Break the Pattern) · อย่าทำให้เด่นทุกอย่าง · 5 วิธี: Perceptual (สี/ขนาด, นิยมที่สุด) · Conceptual/Semantic (ความหมาย: เงาะ ส้ม กางเกง) · Spatial (white space) · Sequential (ลำดับเวลา/ผิดจังหวะ) · Counter (เหนือความคาดหมาย)

Principles of Least Effort (p81–83)

มนุษย์เลือกทางที่ใช้แรงน้อยสุด · 3 องค์ประกอบ: acceptance · responsibility · defenselessness · ทำ Minimize Interaction Cost: Auto-fill, login with Google/Apple, predictive text

Psychologist vs UX Designer (p84–89): เชื่อมกันด้วย Empathy; UX ใช้ Cognitive Psychology ทำ Wireframes/Prototypes/ทดสอบ

Ch3Problem Statement (p2–8)

  • 3 องค์ประกอบ: Current State (ปัญหา+หลักฐาน/ตัวเลข) · Desired State (เป้าหมาย) · Impact (ไม่แก้แล้วเสียอะไร)
  • ห้ามใส่วิธีแก้ (solution) · เน้น "ปัญหา" ไม่ใช่ "ทางออก" · ใช้ข้อมูลและตัวเลข
  • ระบุ User Insight & Pain Point (จาก User Research/Usability Test/Analytics) และ Emotional Impact
  • เทคนิค 5W1H: Who · What · Where · When · Why · How
  • ตัวอย่างดี: "ลูกค้า 30% ทิ้งตะกร้าที่หน้าชำระเงินเพราะโหลด >10 วินาที เสีย 500,000 บาท/เดือน"

Ch3User Persona & Empathy Map (p13–18)

  • Persona = "บุคคลสมมุติ" ที่อ้างอิงข้อมูลจริง
  • ประโยชน์: เข้าใจลึก ออกแบบตรงจุด · สื่อสารตรงเป้า · ประหยัดงบ (scope down) · ทีมไปทิศทางเดียวกัน
  • ข้อมูล: ใคร (demographic) · หมวดหมู่ · ความต้องการ · ปัญหา · ความชอบ · พฤติกรรม · ความคาดหวัง · ช่องทาง · ปัจจัย · การปฏิเสธ

Persona Process: Data Gathering (Interviews, Questionnaire, Surveys, Observation) → Analysis & Synthesis (Pain points, Goals, Behaviors) → Persona Creation (General details, Personality, Needs, Pain points, Behavior when use)

Empathy Map: Think · Say · Does · Feel (รอบ User) + Pain points · Needs · Goals (เครื่องมือ Design Thinking "เอาใจเขามาใส่ใจเรา")

Ch3User Journey Map (p9–36)

Persona → Process → Action → Emotion/Pain points → Idea/Impact

  • Process: Before (ก่อนเข้าถึง/เป้าหมาย) · During (ทำภารกิจ) · After (ความรู้สึกเมื่อจบ)
  • Stage of Process: Scenario (Actor=persona, Trigger=เหตุที่เข้ามาใช้, Environment=บริบท), Conceptual scenario, User Steps/Stages, Goals
  • Action: User Behavior · Difficulty · Awareness (เริ่มรู้ว่ามีปัญหา) · Consideration (เปรียบเทียบตัวเลือก)
  • Emotion (Don Norman Emotional Design): Visceral (แรกเห็น) · Behavioral (ตอนใช้งาน) · Reflective (หลังใช้/ความภูมิใจ ภักดี)
  • Pain point 4: Productivity (เสียเวลา กรอกซ้ำ) · Support (ข้อมูล/ช่วยเหลือไม่ชัด, error ไม่บอกวิธีแก้) · Process (ขั้นตอนซับซ้อน, บังคับ sign up; แก้ด้วย scenario & task analysis) · Design (contrast แย่, ปุ่มเล็กชิด, icon ไม่สื่อ)
  • เครื่องมือหา pain point: Empathy Map · Customer Journey · Usability Test
  • Idea/Impact: Personalization · Micro-interactions · Frictionless Flow · Accessibility

Ch4Vulnerable Groups (p19–45)

  • นิยาม: ICH GCP (ถูกชักจูงง่ายเพราะหวังประโยชน์/กลัวผู้มีอำนาจ) · CIOMS 2016 · NBAC · Declaration of Helsinki · UNESCO
  • เปราะบาง vs ไม่เปราะบาง: ไม่เปราะบาง = Capability + Autonomy
  • 45 CFR 46: Subpart A ทั่วไป · B หญิงตั้งครรภ์/ทารกในครรภ์/แรกเกิด · C นักโทษ · D เด็ก
  • NBAC 2001 (6): Cognitive/Communicative · Institutional (ทหารเกณฑ์ นักโทษ) · Deferential (เกรงใจผู้มีสถานะสูงกว่า: นักศึกษา-อาจารย์, ผู้ป่วย-แพทย์) · Medical · Economic · Social
  • สังคมศาสตร์: ร่างกาย · จิตใจ · สังคม · เศรษฐกิจ

Ch4Privacy, PDPA, Consent (p75–103)

  • Privacy = สิทธิจำกัดการเข้าถึงเรื่องส่วนตัว · ข้อมูลส่วนบุคคล = ระบุตัวได้ทั้งตรง/อ้อม (ไม่รวมผู้ถึงแก่กรรม)
  • Non-private: เลขที่บริษัท, อีเมล/เบอร์ที่ทำงาน, ข้อมูลแฝง (anonymized), ข้อมูลผู้เสียชีวิต
  • Sensitive: เชื้อชาติ, ความเห็นทางการเมือง, พันธุกรรม, พฤติกรรมทางเพศ, ประวัติอาชญากรรม, สุขภาพ/พิการ, ศาสนา/ปรัชญา
  • Confidentiality = กระบวนการปกป้อง privacy · Breach = เปิดเผยโดยไม่ได้รับอนุญาต
  • PDPA: บังคับใช้ 1 มิ.ย. 2565, ต้นแบบ GDPR (EU) · ใช้ข้อมูลน้อยที่สุด · Data Subject / Data Controller (ตัดสินใจว่าประมวลผลอะไร) / Consent
  • สิทธิ: เข้าถึง · ลบ/ทำลาย · คัดค้าน · ถอนความยินยอม
  • โทษ: แพ่ง ค่าเสียหาย + ไม่เกิน 2 เท่า · อาญา จำคุก 1 ปี/ปรับ 1 ล้าน · ปกครอง ปรับ 5 ล้าน
  • ผิด PDPA: CC แทน BCC, CCTV ส่องบ้านคนอื่น, แชร์ข้อมูลข้ามบริษัทในเครือ, เก็บเกินจำเป็น ฯลฯ

Consent

  • Process: Information Sheet → Consent Form → สื่อสาร+ให้เวลา → ลงนาม (Written)
  • Consent by Action (UX): ยินยอมด้วยการกระทำ (ส่งแบบสอบถามคืน/ทำกิจกรรมต่อ), ความเสี่ยงต่ำมาก, ห้ามเก็บ identifier
  • อายุ: <7 ผู้ปกครองเซ็น · 7–12 Assent form ภาษาเด็ก + ผู้ปกครอง · 13–17 เอกสารผู้ใหญ่ เด็ก assent + ผู้ปกครอง · ≥18/20 ผู้ใหญ่เซ็นเอง
  • Waive Consent: ยกเว้นการขอ ต้องผ่านกรรมการเสมอ (เช่น สังเกตการทิ้งขยะที่สถานีรถไฟฟ้า)

Ch5Nielsen's 10 Usability Heuristics (p2–21)

  1. Visibility of System Status: loading %, ✓ บันทึกสำเร็จ, สถานะคำสั่งซื้อ
  2. Match Between System & Real World: ภาษาคุ้นเคย, Bin icon
  3. User Control & Freedom: Undo, Unsend, ปุ่ม X
  4. Consistency & Standards: ปุ่ม/คำเดียวกันทุกหน้า
  5. Error Prevention: ปุ่มเทาเมื่อข้อมูลไม่ครบ, "แน่ใจหรือไม่ที่จะลบ?"
  6. Recognition Rather Than Recall: search suggestion
  7. Flexibility & Efficiency of Use: shortcut Ctrl+C/V (มือใหม่+มืออาชีพ)
  8. Aesthetic & Minimalist Design: ตัดของไม่จำเป็น (ไม่ใช่แค่สวย)
  9. Help Users Recognize, Diagnose & Recover from Errors
  10. Help & Documentation: FAQ

#5 ป้องกันก่อนเกิด vs #9 ช่วยหลังเกิด · #6 search suggestion vs #7 shortcut

Ch5Usability Test Design Process (p22–59)

  1. Define Problem: pain point/ปัญหาที่แท้จริง
  2. Objective & Hypothesis: วัตถุประสงค์ = จะทำอะไร · สมมุติฐาน = คาดเดาผล
  3. Clarify user & sample group: persona, ขนาด/วิธีเลือก/จำนวน, อธิบายเหตุผล
  4. Experimental Design: หาเหตุ-ผลระหว่างตัวแปร ควบคุมปัจจัยแทรกซ้อน
  • กลุ่มตัวอย่างที่ดี: Representativeness · Adequate size · Reliable
  • Task: non-leading + binary outcome (สำเร็จ/ไม่สำเร็จ) · Scenario ให้อิน
  • มี trial ก่อน (ห้ามใช้คำถามจริง) · สุ่มลำดับคำถาม · ถามคล้ายเดิม 3–5 ครั้ง · พักได้ · consent (ถ่ายรูปต้องขอ+อัดคลิป consent) · สรุปยอมรับ/ปฏิเสธสมมุติฐาน
  • เก็บข้อมูล: System Testing/Experiment · Questionnaire (คนเยอะ, primary data) · Interviews · Focus group (6–10 คน) · Observation (เร็วสุด, สถานการณ์เล็ก)
  • Qualitative: Nominal (เรียงไม่ได้: เพศ สี) · Ordinal (เรียงได้: S M L) · Quantitative: Discrete (นับ) · Continuous (วัด: น้ำหนัก)
